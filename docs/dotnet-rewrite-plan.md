## 1. Technology Choices

### Runtime & Framework
- **.NET 8 LTS** (supported through November 2026; .NET 9 is current-term only)
- **C# 12** — file-scoped types, primary constructors, collection expressions
- **Single-file publish**: `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true -p:PublishTrimmed=true -p:IncludeNativeLibrariesForSelfExtract=true`
- **Target**: `net8.0-windows` (not strictly needed, but signals Windows-first intent; `net8.0` alone works too for cross-platform testing)

### NuGet Packages

| Purpose | Package | Version | Notes |
|---|---|---|---|
| CLI parsing | `System.CommandLine` | 2.0.0-beta5 | Mature, Microsoft-supported. Matches Typer's subcommand model well. |
| Console output | `Spectre.Console` | 0.49+ | Rich tables for `test-connection` and `diagnose`. Drop-in for Rich. |
| HTTP client | `Microsoft.Extensions.Http.Polly` | 8.0.x | HttpClientFactory + Polly for retries/timeout. Replaces httpx + manual retry loops. |
| YAML parsing | `YamlDotNet` | 16.x | Mature, widely used. Deserialize to `Dictionary<string,object>`. |
| JSON | `System.Text.Json` | built-in | Source generators for AOT-friendly trimming. |
| Prometheus | `prometheus-net` | 8.x | `Prometheus.HttpListener` for serve mode, `Prometheus.PushGateway` for push. |
| DI | `Microsoft.Extensions.DependencyInjection` | 8.0.x | Standard .NET DI. |
| Logging | `Microsoft.Extensions.Logging` + `Serilog` | 8.0.x / 4.x | Serilog for file rotation + sensitive redaction. |
| Email | `MailKit` | 4.x | Replaces `smtplib`. Modern, maintained, supports STARTTLS. |
| Hashing | `System.Security.Cryptography` | built-in | MD5 for finding state keys (matches Python's `hashlib.md5`). |

### Packages NOT Needed
- **Refit**: Overkill for 5 API endpoints. Raw `HttpClient` + Polly is cleaner.
- **Cocona**: Less mature than System.CommandLine for complex subcommand CLIs.

## 4. Key Interface Signatures

```csharp
// --- Core Models ---
public enum Severity { Ok, Warning, Critical, Error }
public enum MonitorType { RepoHealth, Retention, WorkerHealth, CrossCorrelation }

public record Finding(
    Severity Severity, string Resource, string Message,
    Dictionary<string, object>? Details = null,
    string? MetricName = null, double? MetricValue = null);

public record MonitorResult(
    MonitorType Monitor, DateTime Timestamp, int DurationMs,
    Severity OverallSeverity, List<Finding> Findings,
    string Server = "", List<string>? Errors = null,
    Dictionary<string, object>? Metadata = null);

// --- Monitor Interface ---
public interface IMonitor
{
    MonitorType Type { get; }
    IReadOnlyList<string> RequiredConnections { get; }
    MonitorResult Run(ServerContext serverContext, PatternEngine? patternEngine);
}

// --- Output Interface ---
public interface IOutputHandler
{
    void Emit(IReadOnlyList<MonitorResult> results);
}

// --- Auth Interface ---
public interface ITokenProvider
{
    Dictionary<string, string> GetHeaders();
}

// --- Client Interfaces ---
public interface IVbrClient
{
    List<Dictionary<string, object>> GetRepositoryStates();
    List<Dictionary<string, object>> GetScaleoutRepositories();
    List<Dictionary<string, object>> GetSessions(int lookbackHours = 48);
    List<Dictionary<string, object>> GetJobs();
    List<Dictionary<string, object>> GetBackups();
    List<Dictionary<string, object>> GetRestorePoints(int limit = 500, int offset = 0);
    Dictionary<string, object> GetServerInfo();
}

public interface IVbawsClient
{
    List<Dictionary<string, object>> GetSessions(DateTime from, DateTime to);
    Dictionary<string, object> GetSessionDetails(string sessionId);
    List<Dictionary<string, object>> GetSessionLogs(string sessionId);
}
```

> **Design note**: Client methods return `Dictionary<string, object>` rather than strongly-typed models because VBR API responses are inconsistent (camelCase vs PascalCase, varying field presence). Use a helper extension method to replicate Python's `.get("field", .get("Field", default))` pattern.

## 6. API Clients & Auth

### OAuth2
- `POST /api/oauth2/token` with `grant_type=password` form data
- Cache token with expiry (minus 60s buffer)
- Thread-safe with `SemaphoreSlim` — Python doesn't need this due to GIL, C# does

### HTTP Retry (Polly)
```csharp
services.AddHttpClient("VBR")
    .ConfigurePrimaryHttpMessageHandler(() => new HttpClientHandler
    {
        ServerCertificateCustomValidationCallback = verifySsl
            ? null
            : HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
    })
    .AddPolicyHandler(Policy
        .Handle<HttpRequestException>()
        .Or<TaskCanceledException>()
        .WaitAndRetryAsync(retryCount, _ => TimeSpan.FromSeconds(retryDelay)));
```

### VBR `/api/v1/backups` Pagination
The Python code has a per-item fallback for VBR 13.x HTTP 500 errors on certain backup types. **Port this exactly** — it's a critical reliability feature. When a batch page 500s, fall back to `limit=1&skip=N+i` to isolate bad entries.

## 14. Repo Transition Strategy

**In-place migration with archive branch** (do NOT create a new repo):

1. Create `archive/python-v0.2` branch from current `master` — preserves full Python history
2. Tag the last Python release as `v0.2.x-python-final`
3. Create `dotnet-rewrite` branch from `master`
4. On the rewrite branch:
   - Delete `vhc_monitor/`, `tests/`, `pyproject.toml`, `vhc-monitor.spec`
   - Add `src/`, `tests/` (.NET), `VhcMonitor.sln`
   - Rewrite `.github/workflows/` for dotnet
   - Add `.gitattributes`: `*.cs linguist-language=C#` (fixes GitHub language detection)
   - Keep unchanged: `setup.ps1`, `config/example.yaml`, `LICENSE`, `DCO.md`
5. PR `dotnet-rewrite` → `master`
6. First .NET release tagged as **v1.0.0** — clean major version bump signals the technology change

**Why not a new repo?** Git history, GitHub stars/watchers/forks, and existing links all transfer. Archive branch preserves Python code for reference.

**CI during transition**: `dotnet-rewrite` branch gets .NET CI from day 1. `master`/`dev` keep Python CI until merge. No parallel maintenance — Python is frozen once the rewrite branch starts.

## 18. Risks & Trade-offs

### What Gets Harder

| Risk | Mitigation |
|---|---|
| YamlDotNet dictionary ergonomics (less clean than Python `dict.get()`) | Write `ConfigExtensions.Get<T>()` helpers upfront in Phase 1 |
| VBR API response inconsistency (camelCase vs PascalCase) | Write `GetValue(element, "field", "Field", default)` helper; test with real fixtures |
| Single-file exe size (~30–60 MB vs ~15 MB PyInstaller) | Accept — zero AV hits is worth the size. Add `PublishReadyToRun=true` for startup perf. |
| Thread safety (Python GIL hides bugs) | `SemaphoreSlim` in auth providers, `ConcurrentDictionary` where needed |
| `PublishTrimmed` may break reflection in YamlDotNet / STJ | Test trimmed build in Phase 1; add `[DynamicallyAccessedMembers]` annotations as needed |

### What Gets Easier

| Benefit | Details |
|---|---|
| Zero AV false positives | Native .NET exe won't trigger PyInstaller heuristics |
| Code signing | SignPath Foundation works natively with .NET — no hacks |
| Windows integration | No Python runtime dep, no `sys.stdout is None` guards |
| HTTP client | HttpClientFactory + Polly > manual retry loops |
| Type safety | Compile-time catches for severity comparisons, type mismatches |

## 19. Critical Gotchas (Do Not Miss)

1. **VBR backup pagination fallback**: VBR 13.x returns HTTP 500 for certain `ObjectStorageBackup` entries. Python falls back to `limit=1&skip=N+i` to isolate them. Miss this and real VBR 13.x servers fail silently.

2. **VBAWS date params are ignored by the API**: Hard cap of ~8269 sessions. Client-side date filtering in `WorkerHealthMonitor` is the only filtering. Do not assume the API does it.

3. **Finding resource prefix format**: `[server-name] ` is part of the state file key. Changing the prefix format breaks state files and re-alerts everything.

4. **Exit code = worst finding severity**: Iterate both `result.OverallSeverity` **and** every `finding.Severity`. Miss this and the scheduled task won't signal errors correctly.

5. **Summary mode**: `result.Metadata["summary"] = true` controls whether webhook handlers use summary templates. Handlers must check for this key.

6. **ntfy dedup skip logic**: ntfy handler skips sending when all findings are `_seen_before` and no resolved findings exist. Port the exact logic or users get spam for ongoing issues.

7. **Cross-correlation is per-server**: `CrossCorrelator` groups by `server` field and only correlates within the same server. Cross-server correlation is explicitly NOT done.
